# CONTEXTO DEL CLIENTE — EXPERIENCIA DE RESERVA
(NO COPIAR COMO TEXTO AL SITIO)

Este sitio existe principalmente para reservar.

No se busca una landing tradicional ni convencer con texto.

Asumir que gran parte del tráfico ya decidió reservar y entra para resolver:

"¿Cuándo puedo ir?"

La reserva debe sentirse inmediata.

La disponibilidad es el contenido principal.

Orden esperado:

1. Elegir fecha
2. Elegir horario
3. Elegir servicio
4. Confirmar disponibilidad
5. Pago en línea
6. Crear cita automáticamente
7. Confirmación

Integraciones objetivo:

- Google Calendar como fuente real de disponibilidad
- Pagos en línea
- Evitar captura manual doble

Preferencia de interacción:

Mostrar disponibilidad desde la primera pantalla.

No usar como experiencia principal:

- Formularios largos
- Scroll selector de fecha
- Inputs tradicionales
- Dropdowns escondidos
- Pantallas intermedias innecesarias

La experiencia deseada es más cercana a reservar un vuelo que llenar un formulario.

Preferencia para fecha:

Desktop:
Calendario visible tipo caja.

Mobile:
Puede comprimirse a selector horizontal tipo pills si el espacio lo requiere.

La sensación debe ser:

"Estoy viendo disponibilidad"

más que

"Estoy llenando un formulario"

Contenido como portafolio, precios, servicios, reseñas y ubicación debe aparecer después.
